The public API, the `column.meta` type contract
([Data Grid Types](/docs/components/data-grid-types)), the full keyboard
model, and the async commit contract are final. All eight column types —
`text`, `number`, `currency`, `select`, `boolean`, `date`, `multiSelect`, and
`user` — have working editors. `multiSelect` and `user` share a popover
widget shape neither of the other six need: a borderless trigger (chips
capped at `meta.maxChips`, or an avatar plus name) opening a searchable
command list, with edit mode and popover-open being the same state. Inline row add and delete
(this page's `onRowAdd`/`onRowDelete`) are already final and work with any
column type, since they don't depend on a cell editor existing. Column
resize, pin, and reorder are also final and work with any column type — they
run on TanStack's own column-sizing/pinning/ordering state, not this grid's
own, so they need no wiring to work out of the box.

## Usage

```tsx
import { DataGrid } from "@/components/ui/data-grid"
```

```tsx
const table = useReactTable({
  data,
  columns,
  getCoreRowModel: getCoreRowModel(),
})

<DataGrid
  table={table}
  onCellEdit={(rowId, columnId, value) => {
    // persist the edit however you like — the grid never owns data
  }}
/>
```

The grid never owns `data` — it renders from the `table` instance you create
and own, and reports intent through `onCellEdit`, `onRowAdd`, and
`onRowDelete` only. Declare a column as editable by setting
`meta: { type: "text" }` on its `ColumnDef`; columns without a `meta.type`
render through their normal TanStack `cell` definition (read-only).

## Features

- **Always-rendered live control** — every editable cell is a real control,
  styled borderless and transparent at rest (`hover:bg-accent/30`, a focus
  ring on focus) so a page of mixed column types reads as plain table text,
  not a form. `text`, `number`, and `date` are an `Input` with the matching
  HTML `type`; `currency` is the same input formatted (`$1,234.00`) at rest
  and prefixed with `$` while editing; `select` is a native `<select>`
  restricted to `column.meta.options`; `boolean` is a checkbox; `multiSelect`
  and `user` are a borderless button.
- **multiSelect and user share a popover widget** — settled by prototyping
  three variants; inline toggles and removable chips both lost on the same
  grounds: they let row height vary with content, which the deferred
  virtualization work depends on staying fixed. `multiSelect` shows chips
  from `column.meta.options` (reused verbatim — no parallel option shape)
  capped at `column.meta.maxChips` (default 2) with a "+N" overflow; `user`
  shows an avatar plus name from the static `column.meta.users` list — the
  grid never fetches. Both open onto a searchable command list in a popover;
  edit mode and popover-open are the same state, so typing a character seeds
  the search box and arrows are captured by the list instead of moving
  between cells. `multiSelect` stores a `string[]` normalized to options
  order — so reordering the same set never misfires the commit dedup — and
  commits per toggle with the popover staying open, letting you set several
  tags without reopening the picker. `user` stores a single id or `null` and
  commits-and-closes on pick; "Unassigned" (`null`) is picked the same way as
  any real user, and there's deliberately no `meta.multiple` — a consumer
  who needs more than one assignee uses `multiSelect` instead.
- **Click or type to edit** — clicking a cell or typing a character while it's
  focused enters edit mode and focuses the inner control. <kbd>F2</kbd> also
  enters edit mode, preserving the existing value instead of replacing it.
  `boolean` has no separate edit mode: a click, <kbd>F2</kbd>, or
  <kbd>Space</kbd> toggles and commits it in one step.
- **Commit on blur or Enter** — an edit commits when the control blurs or when
  you press <kbd>Enter</kbd>. <kbd>Escape</kbd> discards the in-progress value
  and returns focus to the cell. `multiSelect`/`user` have no in-progress
  buffer to discard — <kbd>Escape</kbd> there just closes the popover back to
  nav mode without undoing a toggle that already committed.
- **Live validation** — runs on every keystroke and renders as red text under
  the cell, wired through `aria-invalid`/`aria-describedby` on the control. An
  invalid value is never sent to `onCellEdit`.
- **Full keyboard model over `role="grid"`** — arrow keys move between cells;
  <kbd>Tab</kbd>/<kbd>Shift+Tab</kbd> move and **wrap** at row ends (a
  deliberate divergence from generic APG advice, matching spreadsheet
  convention); <kbd>Enter</kbd>/<kbd>Shift+Enter</kbd> move down/up without
  entering edit mode.
- **Roving tabindex** — exactly one gridcell sits in the page's tab order at
  a time; tabbing into the grid from elsewhere lands on that cell, not every
  cell in it.
- **Async commit contract** — `onCellEdit` is always awaited and wrapped in
  the grid's own try/catch, so a synchronous throw and a rejected promise are
  handled identically. A commit shows an inline spinner and disables the
  control immediately, with no delay threshold. On rejection the typed value
  stays on screen — it never reverts — and the error renders with the same
  invalid-cell treatment as a validation error. Committing the same value
  again after a rejection retries it: dedup compares against the last
  _successfully_ committed value, not the last attempted one. Commit errors
  are announced through a reserved `aria-live` region with the cell's
  location; the region stays silent on pending and on success.
- **Inline row add** — passing `onRowAdd` renders a trailing "+ New row"
  control (appends) and a "+" that appears on hover in the gap between two
  rows (inserts after that row). Both call `onRowAdd`, distinguished only by
  whether `afterRowId` is passed, and both autofocus the new row's first cell
  once it appears. The grid never owns data, so it can't build the row
  itself — use the exported `getDataGridRowDefaults(table)` to seed one from
  each column's `meta.type` (`""` for text/date, `0` for number/currency,
  `false` for boolean, the first option for select, `[]` for multiSelect,
  `null` for user).
- **Guarded row delete** — passing `onRowDelete` renders a kebab menu that
  only appears on hover in a trailing column, so the destructive action never
  sits under the cursor during normal editing. Its "Delete row" item opens a
  confirmation dialog; `onRowDelete(rowId)` fires only on confirm. There's no
  optimistic removal and no undo — the row disappears once you hand back data
  without it.
- **Column resize** — every column gets a border-drag handle
  (`header.getResizeHandler()`); double-clicking it resets that column to its
  default width (`column.resetSize()`).
- **Column pin** — a pin icon fades in on header hover and cycles
  unpinned → left → right → unpinned. Pinned columns stick on horizontal
  scroll, offset from TanStack's own `column.getStart()`/`getAfter()`
  measurements.
- **Column reorder** — a "Columns" button in the toolbar opens a panel
  listing columns with drag handles, reordered via native HTML5 drag and
  drop (no extra dependency). Drop position is resolved with a mouse-Y
  midpoint check against the target row, so dragging a column onto its
  immediate neighbor registers as a swap instead of silently no-op'ing.
- **Layout reporting** — resize, pin, and reorder all mutate the `table`
  instance's own state directly, so they work with zero setup. Pass
  `onColumnLayoutChange` to additionally observe that state and persist it.
- **Row selection** — a leading checkbox column renders automatically,
  because TanStack's own row selection feature is enabled by default — no
  separate DataGrid prop to remember. Opt out the same way you would on any
  plain TanStack table: `enableRowSelection: false`. Pass
  `state: { rowSelection }` and `onRowSelectionChange` (as the example above
  does) to make the selection observable outside the grid — needed to read a
  count or build a bulk-action bar. <kbd>Shift+Click</kbd> a row's checkbox,
  or <kbd>Shift+ArrowUp</kbd>/<kbd>Shift+ArrowDown</kbd> from a focused
  gridcell, extends the selection from the last plain click or move — the
  same anchor-and-extend model file explorers use. Selection is row-level
  only; <kbd>Shift+Left</kbd>/<kbd>Shift+Right</kbd> are deliberately left
  unbound for a future cell-range selection. There's no `onBulkAction` prop
  and no action list on `DataGridProps` — the grid doesn't decide what bulk
  actions your domain supports. Compose your own bar from
  [`BulkToolbar`](/docs/components/bulk-toolbar), reading
  `table.getState().rowSelection` for the count and calling
  `setRowSelection({})` to clear, as the example above does. A bulk delete is
  just your selected row IDs looped over the same `onRowDelete(rowId)` you'd
  wire up for single-row delete — there's no second delete path.
- **Narrow-container card list** — measured with a `ResizeObserver` on the
  grid's own container, never a viewport media query: the driving case is a
  desktop user dragging a workspace pane divider, not a phone. Below a 448px
  container, `narrowFallback="cards"` (the default) swaps `role="grid"` for a
  plain list — only one tree ever renders, never a CSS-hidden second one — so
  this composes with the deferred virtualization work. Each row becomes a
  card: the first column is the title and the next two the subtitle,
  positional by column order unless overridden per column with
  `meta.summary`. Tapping a card opens a swipeable bottom drawer — dragged
  down or dismissed via its swipe handle, the same bottom-to-top transition a
  sheet would use — with every column as a labelled, bordered field, a
  deliberate divergence from the borderless-at-rest wide-branch styling,
  since an editable field should look unambiguously editable in this layout.
  Drawer fields commit through the exact same `onCellEdit` callback and
  pending/error handling as the wide branch; `multiSelect` and `user` toggle
  inline instead of through a popover, and `select`/`boolean` commit
  immediately on change. The narrow branch is a list, not a grid: the
  roving-tabindex/F2/Tab-wrap keyboard model doesn't apply, the hover-gap "+"
  insert is dropped (adding is append-only), delete moves into the drawer's
  footer, Shift range-select is dropped (selection is
  tap-per-row), and resize/pin/the Columns panel don't render. The `aria-live`
  region is shared across both branches, not duplicated. Pass
  `narrowFallback="none"` to keep the real grid at any width instead, with
  the first column stuck sticky-left so it stays visible under horizontal
  scroll.
