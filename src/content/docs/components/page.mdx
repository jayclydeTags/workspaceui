## Usage

```tsx
import { Page } from "@/components/ui/page"
```

`Page` is a set of parts you compose, not a single component with props for
every slot. `Page.Root` is the shell; put a `Page.Header` and a `Page.Content`
inside it.

```tsx
<Page.Root>
  <Page.Header>
    <Page.Heading>
      <Page.Title>Settings</Page.Title>
    </Page.Heading>
    <Page.Subtitle>Manage your account</Page.Subtitle>
  </Page.Header>
  <Page.Content padded>{/* page content */}</Page.Content>
</Page.Root>
```

### Composition

Every part is optional, so leaving one out removes it:

```tsx
<Page.Root>
  <Page.Header>
    <Page.Heading>
      <Page.Visual>{/* icon */}</Page.Visual>
      <Page.Breadcrumbs
        items={[{ label: "Settings", href: "/settings" }, { label: "Billing" }]}
      />
      <Badge>Beta</Badge>
    </Page.Heading>
    <Page.Actions>
      <Button size="sm">Save changes</Button>
    </Page.Actions>
    <Page.Subtitle>Manage your subscription and invoices</Page.Subtitle>
  </Page.Header>
  <Page.Content padded>{/* page content */}</Page.Content>
</Page.Root>
```

- **No header**: leave out `Page.Header` — the page then has no `<h1>`, so render your own heading in the content if it still needs one.
- **Title and breadcrumbs**: `Page.Title` is always the page's `<h1>`. A `Page.Breadcrumbs` trail renders no heading of its own, so when the trail is the visible heading, add `<Page.Title className="sr-only">` with the current page's name beside it. Compose the trail from the shadcn `Breadcrumb*` items (`BreadcrumbItem`, `BreadcrumbLink`, `BreadcrumbPage`, `BreadcrumbSeparator`).
- **Badge**: any node placed in `Page.Heading` sits next to the title (or the last breadcrumb); there is no dedicated badge part.
- **Subtitle** always takes its own row, wherever it sits in the header. `Page.Subtitle` and `Page.Actions` are laid out by `Page.Header`'s wrapping row, so use them inside it.

Each part is also exported by name (`PageRoot`, `PageHeader`, …) if you'd
rather not use the namespace. The parts have no shared state, so they work
outside `Page.Root` too, but the shell layout (`flex h-full flex-col`) comes
from the root.

## API Reference

### Page.Root

The shell. Fills its parent (`flex h-full flex-col`) and stacks the header over the content.

| Prop        | Type              | Default | Description                                         |
| ----------- | ----------------- | ------- | --------------------------------------------------- |
| `className` | `string`          | -       | Additional CSS classes applied to the root element. |
| `children`  | `React.ReactNode` | -       | `Page.Header` and `Page.Content`.                   |

Any other `div` prop (`id`, `data-*`, `aria-*`, `style`, `onClick`, ...) is forwarded to the root element.

### Parts

| Part            | Renders    | Description                                                                                                                                                                                                          |
| --------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Page.Header`   | `<header>` | The header landmark. A wrapping row holding `Page.Heading`, `Page.Actions` and `Page.Subtitle`. Leave it out for a page with no header.                                                                              |
| `Page.Heading`  | `<div>`    | Left side of the header: a row for `Page.Visual`, `Page.Title` or `Page.Breadcrumbs`, and any badge.                                                                                                                 |
| `Page.Visual`   | `<span>`   | Decorative visual (icon, image, illustration). Hidden from assistive tech (`aria-hidden`).                                                                                                                           |
| `Page.Title`    | `<h1>`     | The page's heading — always render one, with `className="sr-only"` when a breadcrumb trail is the visible heading. A string child is also set as the `title` attribute, so a truncated title shows in full on hover. |
| `Page.Actions`  | `<div>`    | Right-aligned actions in the header.                                                                                                                                                                                 |
| `Page.Subtitle` | `<p>`      | Secondary line under the heading, always on its own row. A string child is also set as the `title` attribute.                                                                                                        |

Each part forwards `className` and the props of the element it renders.

### Page.Breadcrumbs

A `<nav aria-label="breadcrumb">` around a non-wrapping list. Its children are the shadcn `BreadcrumbItem`s and `BreadcrumbSeparator`s; links and the current page truncate. It renders no heading — pair it with a `Page.Title className="sr-only"`.

| Prop        | Type              | Default | Description                                                      |
| ----------- | ----------------- | ------- | ---------------------------------------------------------------- |
| `className` | `string`          | -       | Additional CSS classes applied to the `<nav>`.                   |
| `children`  | `React.ReactNode` | -       | `BreadcrumbItem` and `BreadcrumbSeparator` elements, root first. |

Any other `nav` prop is forwarded.

### Page.Content

| Prop        | Type              | Default | Description                                                   |
| ----------- | ----------------- | ------- | ------------------------------------------------------------- |
| `padded`    | `boolean`         | `false` | Adds padding around the content.                              |
| `className` | `string`          | -       | Additional CSS classes applied to the content element.        |
| `children`  | `React.ReactNode` | -       | The page content. This area scrolls (`flex-1 overflow-auto`). |

### Router-aware breadcrumbs

`BreadcrumbLink` takes `render` to swap the anchor for a router `Link` (e.g. Next.js's), so navigation is client-side instead of a full page load:

```tsx
<Page.Breadcrumbs>
  <BreadcrumbItem>
    <BreadcrumbLink render={<Link href="/settings" />}>Settings</BreadcrumbLink>
  </BreadcrumbItem>
  <BreadcrumbSeparator />
  <BreadcrumbItem>
    <BreadcrumbPage>Billing</BreadcrumbPage>
  </BreadcrumbItem>
</Page.Breadcrumbs>
```
